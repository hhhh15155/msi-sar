# Baseline 适配规则

本规则由根目录 [AGENTS.md](../../AGENTS.md) 要求所有 agent 执行；[项目 skill](../../.agents/skills/msi-sar-baseline-adaptation/SKILL.md) 是操作入口。适用于用户要求引入、集成、适配新 baseline 或对齐其配置的实现任务。只读调研、仅收录源码的明确请求保持原范围；安装、服务器操作和实验运行仍按用户授权执行。

## 交付范围

用户说“把某模型加为本项目 baseline”，默认包含主动完成 MSI–SAR 适配，不需要用户再次提醒。对核心源码齐全的模型，完成下述实现与检查后再交付；不得只建 vendor 目录、README 或 YAML 就标成已集成。

如果源码缺失核心双模态结构、关键算子不可用，或最小适配会改变原方法核心机制，记录确切文件、符号、张量或依赖阻塞；能独立完成的部分继续完成。不得编造缺失网络，不能以插值复制波段、随意重建辅助分支等方式冒充原方法。需要用户选择的结构变更应说明具体方案。不得把“本机缺少 PyTorch”写成验证通过。

## 模型与输入

1. 开始时核实本地目录、分支、HEAD、工作区和适用的 AGENTS.md；保留已有用户改动。核实作者仓库、固定 commit、核心源码和许可证；vendor 保留只读快照，适配代码放在项目包装层。缺少许可需明确记录，不能声称已获任意复用授权。
2. 读取共享 `configs/datasets/` 与 [数据集说明](../datasets/README.md)，按实际通道顺序分流。YRD、YRD2509NEW 为 MSI 10＋SAR 4；GRSS07 为 MSI 6＋SAR 1。训练 YAML 显式写出模态通道数，类别数从数据配置读取，校验总通道和标签映射。不能只把 HSI／LiDAR 变量改名而保留不适用的输入假设。
3. 项目 `PatchDataset` 输出 `[B,1,C,H,W]`，MSI 在前、SAR 在后；模型包装返回 `[B,num_classes]`，供交叉熵使用的稳定 logits。适配原实现的双输入、字典／元组输出、概率输出等接口，不能对概率重复 softmax 后直接当 logits 训练；若需改变输出头，保留核心分类机制并记录差异。
4. patch 默认 11，保持可配置；若仅支持奇数或存在最小尺寸，在入口明确校验。逐层推导 6／10 MSI 通道下的 3D 光谱核、谱维展平、分组卷积、token／注意力／位置编码和分类头尺寸；不能硬套 PCA30、144 波段或固定 patch13 的形状。SAR 分支适配 1／4 通道；不把 LiDAR 高度含义当作 SAR 物理含义。
5. 保留原方法核心，修改限于必要接口与形状适配。注意原模型宽度参数的语义，不能把 FM16 随意换为64后忽略后续64维 token。无验证收益时不新增融合模块，不因“优先非 Mamba”删除既有基线。
6. 所有可训练参数在构建优化器前注册，特别是动态滤波基、FVE、位置编码。检查设备迁移及 checkpoint 保存／重载；路径相对仓库／模块解析，不保留搬迁前的 vendor 路径，不依赖 import 时读取数据或启动训练。

## 训练、评估与配置

当前完整数值协议以 [实验说明](../experiments/README.md#数据与协议仍然有效) 为主要维护位置，实际运行仍以 YAML 与调用链核对。新 baseline 自动提供 YRD fs50、YRD2509NEW fs50、GRSS07 custom 三份配置，复用共享数据配置、相同划分工具和逐通道整图归一化。不得为每个模型复制一套易漂移的数据定义。

默认 5 seeds `202201–202205`，patch11，200 epochs，train128／test1024，FP32，Adam（lr `0.001`、weight decay `0.0001`），无预训练。模型特有的必要差异要在 README 逐项说明，不做隐式调参。

每次只评估训练结束的最终 checkpoint，不用测试集选 epoch 或超参数。全部预定运行完成后，`eval.run_index: best` 根据各次**测试集 OA** 选最高者出图；并列按配置顺序取首个。图的元数据／日志记录 run、seed、测试 OA 和选图依据。保留每次指标与全部运行的均值／标准差；最高一次不能冒充平均结果。若某次失败，记录缺失并报告不完整，不悄悄用少量运行冒充完整 5 次结果。

测试与出图是独立操作。正式测试及 `evaluate_run` 仅推理保存的测试划分并计算指标，不先做全图推理。默认训练结束后用测试 `metrics.json` 选择 OA 最高的运行，`save_labeled_maps` 对**全部有标注位置**推理出图，包括训练位置是预期行为，不能改为只画测试位置。未标注位置保持背景；出图不重新计分、不产生混合指标、不覆盖测试文件，只写图和 `labeled_map_info.json`（run、seed、既有测试 OA、选图依据）。

全图是另一种出图方式，由 `save_full_map` 对所有像元推理。默认 `infer.save_full_map: false`，训练／重评估入口均不自动调用；用户明确需要时运行独立 `infer_<model>.py --mode full`。两种出图均默认用保存测试 OA 最高的模型。训练、重评估和出图对同一个 checkpoint／测试掩码应有一致预测。

## 验证与状态

- 引入实现任务包含相称的检查：首先做路径存在性、语法、配置一致性及张量维度检查；环境已有依赖时，用小批量合成数据验证两种通道组合、输出尺寸与有限数值、一次前向／反向、优化器参数覆盖以及 checkpoint 重载一致性。这是合成数据检查，不启动真实训练或全图推理。
- 如环境缺失依赖，不自动安装或升级；记录未验证项目。未经明确授权，不上服务器运行模型，不启动数据集训练、全图推理、批量调度，也不重跑已完成实验。授权新任务执行后，只完成指定范围内的未完成项。
- 仅静态检查通过：标注“已适配、未运行验证”；合成数据检查通过：标注“合成数据验证通过、未完成正式实验”；只收录／有阻塞：标注“未适配”或“适配受阻”，写清原因。三者均不能当作已复现论文精度。配置对齐不证明模型可运行。

## 文件与完成条件

每个可集成 baseline 提供 `baselines/<model>/{model,train,eval,infer,dataset,io,metrics}.py`、`__init__.py`、README；可复用共享实现。提供 `scripts/train_eval_<model>.py`、已有 run 的 `scripts/eval_<model>.py` 与 `scripts/infer_<model>.py`，或明确可执行的等价 CLI；不能只在文档列出不存在的脚本。

同步维护 [基线索引](../../baselines/README.md)、[模型索引](README.md)、[配置索引](../../configs/README.md)、[脚本索引](../../scripts/README.md) 与 vendor 来源说明。专用 README 记录来源 commit、许可证、接口、原方法差异、实际命令、预训练和验证状态。运行身份记录配置／数据配置快照、代码版本与未提交改动、种子、划分、环境、checkpoint 及指标位置。

交付时逐项列出：已完成的适配、修改文件、实际验证命令与结果、尚未验证／受阻项。用户仅要求引入模型时，不把“待运行正式实验”当作实现任务未获授权的理由而停在源码收录阶段。
